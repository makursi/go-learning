# 笔记与练习

一次调用落一个主题：一篇笔记，加一组能单独跑起来的练习。笔记记理解，练习做验证；练习从笔记的小节里长出来，题号顺序就是小节的顺序。

## 1. 定主题与落点

主题没指定就先问用户。然后看 `src/notes/` 与 `src/homework/` 里现有的主题编号，定下三个名字：

- `<topic>`：`NN-slug`。已有主题沿用，新主题取下一个编号。
- 笔记 slug：知识点名，如 `channel`、`array-slice`。
- 作业名：与笔记 slug 相同，落在同一个 topic 下。

落点：`src/notes/<topic>/<slug>.md` ↔ `src/homework/<topic>/<homework>/<NN-exercise>/main.go`。

**完成条件**：三个名字定下来，编号和现有目录对得上。

## 2. 生成骨架

```sh
go run ./tools/scaffold note --title "中文名（English）" <topic> <slug>
go run ./tools/scaffold exercise <topic> <homework> <exercise-slug>
```

flag 写在位置参数之前。题号由工具分配。没有 `--force`，已存在的文件一律跳过；slug 写错就删掉重生成。完整用法见 `tools/scaffold/README.md`。

**完成条件**：两条命令都退出 0，目标路径存在。

## 3. 写笔记

先读官方文档或规范，再动笔。笔记里的事实要能追到来源，不凭记忆写。来源从 `README.md` 的文档清单里挑：规范和官方文档为准，博客只作补充。

- 标题写 `# 中文（English）`，与生成时的 `--title` 一致。
- 开头一句写清来源与范围：依据哪份规范或文档，覆盖到哪里。
- 小节按学习顺序排：是什么、怎么用、哪里会错。小节顺序就是练习的题号顺序。
- 先给原文再解释：语法引产生式，行为引官方文档，然后写中文解释。
- 每个小节配一个最小示例。能编译的 Go 代码用带 `go` 标记的围栏，语法和输出片段用无标记围栏。
- 术语首次出现写 `中文（English）`，代码注释用中文。
- 结尾写一节「常见注意点」，收易错边界：nil、零值、越界、并发、顺序不确定。

**完成条件**：每个小节都有例子或规范原文，没有只写标题的空节；按小节标题读一遍，能覆盖这个知识点的定义、用法和边界。

## 4. 出练习

笔记写完再出题。一道题只验证一个动作或一条结论。

- 从要动手的小节里选题，题号从 `01` 起，顺序和小节一致。题 slug 说这道题验证什么，不写类型名。
- `main.go` 第一行是 `// 题目：`，写两件事：验证什么，具体做什么、打印什么。
- 一道题一份 `main.go`、一个 `func main()`。辅助函数、类型、方法留在同一文件。
- 输出是能核对的具体值，不是只打印 `ok`。
- 中文注释标在非显然处：这一行为什么这样写、这行验证什么。
- 换一个场景或数据，不照抄笔记里的示例。
- 题面写进 `// 题目：`，不另建文件。题与题之间不共享代码。
- 顺序不对就用 `git mv` 改目录名：题与题互不引用，重命名不影响编译。

**完成条件**：每道新题 `go run ./src/homework/<topic>/<homework>/<NN-slug>` 退出 0，输出与题面写的要求对得上；题号从 `01` 起连续。

## 5. 对齐与门禁

拿笔记的小节标题过一遍题目：每道题都能指回一节，该配题的小节不缺。写不出题的小节就空着，不为凑对齐造题。

然后按 `AGENTS.md` 跑门禁三条。

**完成条件**：门禁三条全过。
