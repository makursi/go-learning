# Spec：作业结构改为「一题一目录」（每道题自带 `main`）

## Problem Statement（问题陈述）

写作业时最大的痛苦不是做题，是**给函数起名**。Go 没有文件作用域：同一个 `package` 里所有顶层 `func`、`type`、`const`、`var` 共享一张名字表。而现行结构是「一个主题一个目录、一题一个 `.go` 文件、共用一个 `package main`」，于是每加一道题，除了给它想一个入口函数名，还要给它的辅助函数、类型再想一批**全包唯一**的名字。名字表压力因此溢出到各处：

- **辅助函数被迫各自造名，风格已经分裂成五套**：`channel` 里「一次性发送器」有 `sendOne`、`sendTwo`、`workerA`/`workerB`、`double` 四种写法；`goroutine` 里 `hello`、`makeGoroutine`、`makeWaitGroupExample`、`notifyExample`、`download` 三套前缀并存。50 个题目文件里 20 个带这类辅助函数。
- **类型撞名只能靠改名回避**：`data-type/06` 的 `Book` 撞了 `07` 的同名类型，只能叫 `Book2`，注释里还要自认这一刀。
- **撞到语言内置**：`go-function/01-max.go` 的 `max` 遮蔽了 Go 1.21+ 的内置 `max`。
- **第二处代价：单题不可跑**。`02-concurrency/channel` 的 `07`、`08` 一跑就 deadlock，只能排除在 `main.go` 调度外；`07` 的题面直接教读者「把 `main` 里的调度临时改掉再 go run」——结构已经在逼人手改调度文件。而 Go 原生也没有「跑全部」的命令：`go run ./...` 拒绝匹配到多个包，`go run ./a ./b` 会把后面的当作被运行程序的参数（均实测）。
- **工具只覆盖第一步**：`scaffold homework` 只生成一个四行的 `main.go`，不生成题目文件、不写 `// 题目：`、不接调度；「`NN-slug` ↔ 入口函数」这条约定全仓零强制，纯靠手写与人审。

三周前（2026-10-28，issue `#39`–`#51`）刚把 11 个目录整理成「一题一文件」。那次解决了「文件名不说明题目」的问题，但没有、也无法解决「命名空间只有一个」。

## Solution（方案）

把命名隔离的层级从「文件」换到「包」：**一道题一个目录、一个 `package main`、一个 `main()`**。

- 落点：`src/homework/<topic>/<NN-slug>/main.go`。`NN` 是这道题在该主题内的学习顺序（两位补零），`slug` 说明这题验证什么。题目注释仍在文件顶部、`package` 之前，以 `// 题目：` 开头。
- 每道题自己是一个可执行目录：`go run ./src/homework/<topic>/<NN-slug>` 单独跑；题目内部的辅助函数、类型、泛型函数随便叫，跨题永不撞名；`go build ./...` 仍然一次覆盖全部。
- 主题目录不再有调度用的 `main.go`，它只是一个题目目录的容器。
- `scaffold` 的 `homework` 种类换成 `exercise`：`scaffold exercise <topic> <slug>` 自动取下一个题号，生成带 `// 题目：` 占位与空 `main()` 的骨架——「每加一题手写文件头」这件被 `第四轮` 记为待定的事，现在结案。
- 迁移现有 50 道题（不对任何题目的逻辑与输出做改动），删掉两个空壳主题，把 `Book2` 改回 `Book` 作为「撞名消失」的第一处证据。

## User Stories（用户故事）

1. 作为学习者，我想让每道题自己占一个包，这样我给辅助函数起名时不必再检查别的题目有没有用过这个名字。
2. 作为学习者，我想在题目内自由使用 `helper`、`result`、`Person`、`Map[T]` 这类通用名字，这样我不用为了避开撞名而牺牲名字的准确。
3. 作为学习者，我想让 `Book2` 这种「因为撞名只能加序号」的名字消失，这样类型名可以恢复本来该有的样子。
4. 作为学习者，我想让 `max` 不再遮蔽语言内置，这样我写的辅助函数名与标准库、内置标识符的冲突不再是结构逼出来的。
5. 作为学习者，我想让每道题能被单独 `go run`，这样我复习一道题时不必先翻调度文件。
6. 作为学习者，我想让会 deadlock 的题（`07`、`08`）成为各自独立的可执行目录，这样「跑一下看它死锁」本身就是这道题要观察的现象，而不是需要手改 `main.go` 的例外。
7. 作为学习者，我想让题号继续表达学习顺序，这样目录列表的顺序仍然和笔记里的顺序一致。
8. 作为学习者，我想让新增一道题只敲一条命令，这样我不用手写文件头、不用自己算下一个题号、不用回调度文件补一行。
9. 作为学习者，我想让骨架生成器写出来的文件一落地就过 `gofmt`，这样格式问题不占我的注意力。
10. 作为学习者，我想让题目注释仍在文件顶部、仍在 `package` 之前，这样我打开文件第一眼看到的就是题面。
11. 作为学习者，我想让迁移后的每道题输出与迁移前逐字一致，这样这次改动可以被信任为纯结构整理。
12. 作为学习者，我想让「一道题一个包」这条规则写明禁止跨题共享辅助代码，这样下次想复用 `mustParseInt` 时我知道该把它放进笔记或带测试的工具包，而不是往作业里塞。
13. 作为 agent，我想只读一个题目目录就能回答「这道题验证什么、入口在哪」，这样不必先把整个主题目录读完。
14. 作为 agent，我想让「这个目录里只有一个 `main.go`」成为可校验的形状，这样我不必猜哪份文件是入口。
15. 作为 agent，我想让新增题目的命令自己处理编号，这样我在实现时不会接到「编号冲突」这类报告。
16. 作为维护者，我想让仓库约定、术语表、设计笔记与目录实际形状一致，这样「文档说的」不再和「目录里长什么样」对不上。
17. 作为维护者，我想让税与术语分开：`Homework` 指一整个主题的题目集合，`Exercise` 指单道题目目录，这样两个词不再互相指代。
18. 作为维护者，我想让这次改动有 spec 与第五轮设计记录，这样「为什么又改回一题一目录」只推导一次，不会在下次会话里被重提。
19. 作为维护者，我想让 `homework` 命令干净地消失（未知种类、退出码 2），而不是留一个「已改名为 exercise」的特判，这样工具里不会长期住着一个过渡期补丁。
20. 作为维护者，我想让 `--dry-run`、幂等、`skip`、退出码这些既有运行时契约逐字不变，这样脚本和肌肉记忆都不用重学。
21. 作为维护者，我想让编号规则保持不变：主题编号仍由人显式给出，题号由工具分配，这样「跨仓身份」与「目录内顺序」这两种编号不会混成一套。
22. 作为维护者，我想让两个空壳主题干净消失，而不是在新形状里留下「没有题目的主题目录」。
23. 作为维护者，我想让这次迁移用 `git mv` 保留历史，这样我回看某道题以前的写法时不会被截断。
24. 作为未来的我，我想在代码里读到一个明确的边界：题目之间不共享代码，这样「作业是独立答案」这条性质不会被渐进式地破坏。

## Implementation Decisions（实现决策）

**命名空间与形状**

- 每道题是一个独立 `package main`，落点 `<topic>/<NN-slug>/main.go`。包内一切顶层标识符只在本题内有效，因此跨题零冲突；这是本次改动的全部理由，其余都是它的推论。
- 禁止跨题共享辅助函数、类型、常量。需要复用的东西只有两个去处：笔记里的代码块，或 `tools/` 里带测试的包。这一条要写进 `AGENTS.md` 与术语表，否则隔离会被下一次「顺手复用」侵蚀。
- 主题目录不再是 Go 包，不再有调度 `main.go`。「一次跑完整个主题」不再是 Go 命令的能力，需要时用一行 shell 循环或未来的 `scaffold run`（本 spec 之外）。
- 题目注释、`package main`、`func main()` 的相对位置固定：注释在最上方、`package` 之前；`main()` 为空骨架，由人填。

**入口函数**

- 原先「文件名 ↔ 入口函数」的绑定取消：入口就是 `func main()`，不再保留 `UnbufferedChannel()` 这类包装函数，也不额外加 `func main() { Xxx() }` 的壳。
- 迁移时对每道题只做两件事：改入口函数名为 `main`、把文件搬进同名目录。题目内部的其他顶层定义原样保留。

**编号**

- 题目编号由工具分配：扫描 `<topic>/` 下现有的 `NN-*` 目录，取最大编号 +1，两位补零；用尽 99 时报错并提示放宽编号规则（沿用主题编号的提示风格）。
- 这是对 `第二轮`「编号显式、不接受只给名字让工具分配」的**有意例外**，理由：题号是目录内的追加顺序（append 语义），不是跨仓身份；主题编号仍然显式，因为它要与笔记对齐、要有意义。
- `slug` 仍由人给出，规则不变（小写连字符，描述这题验证什么）。

**命令面**

- `scaffold exercise [--dry-run] <topic> <slug>`，flag 必须在位置参数之前（标准库 `flag` 语义）。
- `homework` 走未知种类路径：stderr 报错、退出码 `2`、不写任何东西，**不留**「已改名为 exercise」的特判（与第三轮砍 `lecture` 同一处理）。
- `note` 种类与行为逐字不变。
- 种类表仍是内容区结构的唯一权威：`exercise` 是表里的一行（目录形状 + 内容生成器），判定逻辑不动。

**模板与运行时契约**

- 骨架内容：`// 题目：` 占位注释、空行、`package main`、空 `main()`。tab 缩进、结尾换行，生成即可过 `gofmt`。
- `exercise` 不接受 `--title`（题面由人写，不预置假内容）。
- 运行时契约逐字不变：`O_EXCL` 创建、已存在则 `skip`、无 `--force`、`--dry-run` 不落盘且输出与真实运行逐字一致、每行 `create|skip <仓库相对路径>`、结尾 `N created, M skipped`、错误加 `error:` 前缀、退出码 `0/1/2`。

**迁移**

- 范围：11 个非空主题目录里的 50 个题目文件 → 50 个题目目录；两个空壳主题（`go-if`、`mutex-and-rwmutex`）直接删除，不留占位（git 不留空目录，写题时用 `exercise` 现生成）。
- 纯整理：不改任何题目的逻辑、题面要求与输出。
- 验收：迁移前为每个主题留基线输出，迁移后逐题跑并拼接比对；对 map 遍历顺序这类不确定的输出，先跑两遍筛出不稳定的白名单，再按排序后比较。
- `Book2` 改回 `Book` 并删掉解释撞名的注释，前提是输出不变（类型名不进输出）——这是「撞名消失」的首个证据。
- 空壳删除与旧措辞清扫放在最后一张票（收尾），与第四轮「先整理、后收尾」一致。

**文档同步**

- `AGENTS.md`：目录约定表里 `src/homework/` 的形态改为「一个主题一个目录，目录内一题一目录、各自 `main.go`」；正文替换「一题一文件 / 文件名绑入口函数 / main.go 只做调度」三条，补「跨题不共享代码」护栏，补「不再有主题级调度文件」。
- `GLOSSARY.md`：`Homework` 改为「一个主题下的题目集合，无调度入口」；`Exercise` 改为「一个题目目录 + 自带 `main()` 的 `package main`，题面在顶部注释」。
- `docs/agents/design-notes.md`：新增第五轮（问题 / 已定分支 / 已否分支 / 待定分支），顶部状态行同步。
- `docs/specs/`：本 spec 快照。
- `tools/scaffold/README.md`：命令示例与「生成之后怎么写题」换成 `exercise`。

**交付**

- 分支 → 提交 → PR → 等用户确认 → `--squash` 合并。提交按「工具一刀 / 一个主题一刀 / 文档一刀」切，回滚粒度 = 一个主题。

## Testing Decisions（测试决策）

**什么算好测试**

只测外部可观察行为：进程退出码、stdout/stderr 文本、磁盘上最终生成的文件与路径。不测内部函数、不 mock 文件系统——工具的价值恰是「路径与编号不会错」，这只有端到端才验得出来。

**seam**

- 仓库当前只有**一条** seam：`scaffold` 的 CLI 边界（参数 + 工作目录 + 两个输出流 → 退出码）。`exercise` 的测试全部从这条既有 seam 进入，**不新增 seam**。
- 内容区（迁移后的 50 个题目目录）不写测试：作业按仓库约定不配 `_test.go`，本次也不因为「换了形状」而破例。它的正确性用「门禁 + 逐题基线比对」表达。

**测什么**

- `exercise` 的落点与文件内容：目录名是 `NN-slug`、目录内只有 `main.go`、内容含 `// 题目：` 占位与空 `main()`。
- 骨架的合法性：过 `format.Source` 不变，且 `go/parser` 能解析（沿用现有断言方式）。
- 编号：空主题从 `01` 起；已有 `01`、`03` 时取 `04`；两位用尽时报错并提示。
- 未知种类表补一行 `homework`（走未知种类、退出码 `2`、不落盘）。
- 既有契约的回归：`--dry-run` 不落盘且输出与真实运行逐字一致、幂等 `skip`、只建该种类的树、仓库外拒绝、退出码 `0/1/2`。
- 内容区验收：`gofmt -l .` 无输出、`go vet ./...`、`go build ./...` 全绿；每道题 `go run` 输出与基线一致。

**先例**

`tools/scaffold/test/` 的外部测试包（`package scaffoldtest`，只经 `Run` 进入，在 `t.TempDir()` 里造带 `go.mod` 的假根、用真文件系统断言）。本次的用例按能力并入既有文件，不新建测试包。

## Out of Scope（不在本次范围）

- `scaffold run`（跑一个主题全部题目、`--only`、`--keep-going`）：记为待定分支，触发条件是「用一行 shell 循环跑全部时觉得烦」。
- `scaffold check`（校验编号连续性、目录内只有 `main.go`、注释在顶部）：单独一票，排在文档改口之后。
- 新增题目内容、补写 `go-if` 与 `mutex-and-rwmutex` 的题目。
- 主题编号重排、笔记目录调整。
- 作业配 `_test.go`、引入批量运行脚本、加 CI。
- 为本次改动写 ADR：可逆（改回一题一文件只是再迁一次），理由留在设计笔记即可。
- 重写 git 历史：迁移用 `git mv`。

## Further Notes（补充说明）

- **为什么推翻第四轮**：第四轮否掉「一题一目录」的三条理由是「目录数四倍、题目注释散进各自 `main()`、检索变三层」。事实核查后，第二、三条不成立或可缓解——注释在一题一文件形态下同样散在每个文件顶部；检索层数是 `homework/<topic>/<NN-slug>/main.go` 与 `homework/<topic>/<NN-slug>.go` 之差，且目录名保留了 `NN-slug` 的可读性。真正成立的是「目录数四倍」，它的代价已由本 spec 的用户故事承担，收益是命名零摩擦与单题可跑。第四轮的核心成果（`NN-slug` 编号、题目注释在顶部、一次统一所有主题）全部保留。
- **第四轮留下的待定项结案**：「`scaffold` 是否增加参数生成题目文件骨架——等真正觉得烦了再说」。现在结案为「是」，并顺带解决了被第四轮否掉的「让 `scaffold` 直接生成题目文件」。
- **现状核实（2026-11-20）**：作业区 50 个题目文件、14 个 `main.go`、2 个空壳主题；包级 `var`/`const`/`init()` 为 0；`文件名 ↔ 入口函数` 50/50 成立；20/50 文件带辅助函数；类型撞名一例（`Book`/`Book2`）；`max` 遮蔽内置一例；`channel/07`、`08` 因 deadlock 未接入调度。
- **Go 原生不支持「跑全部」**（本次实测）：`go run ./...` 报 `pattern ./... matches multiple packages`；`go run ./a ./b ./c` 只运行 `a` 并把 `./b ./c` 当作它的参数，退出码 `0`。所以「一次跑完一个主题」必须由 shell 循环或未来的工具命令承担。
- **注释里的题面不改**：迁移只动入口函数名与文件位置，题面文字、题目顺序、输出全部保持原样。
