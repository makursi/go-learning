# Spec：工具区 CLI（`scaffold`）

## Problem Statement（问题陈述）

每次开始一个新知识点，都要在内容区的三棵树里手工造路径：一个笔记文件、一个讲义目录、一个作业目录。路径规则写在 `AGENTS.md` 里，但没有任何东西执行它——编号要靠翻 `src/notes/` 数出来，slug 的大小写与连字符靠记，`package main` 加空 `main()` 的骨架每次重敲一遍。

这个仓库目前一个 Go 文件都没有，所以连可以抄的样板都不存在。实际后果是：开新主题变成一次容易出错的手工劳动，错了要等 `go build` 或 `go run` 才暴露；同类内容的成果也长得不一致（有的作业目录里有 `README.md`，有的没有）。

## Solution（方案）

在工具区 `tools/scaffold/` 放一个零依赖的小 CLI，一条命令落一个条目。它承担三件人容易记错的事：

1. **把「种类 → 路径」变成代码**：工具是这项规则唯一的执行者，笔记 / 讲义 / 作业的落点由它决定，不由我记忆决定。
2. **在写入前拒绝不合规的输入**：主题编号与名字按 slug 规则校验，失败时顺手告诉我下一个可用编号。
3. **一次写对骨架**：讲义与作业的 `main.go` 立刻可 `go run` 且 `gofmt` 干净；笔记的标题按「术语首次出现写 `中文（English）`」的约定填。

一次调用只落一个种类的一个条目，只建它用到的那棵树。它不碰索引，不出现任何代码在 `src/` 下。

## User Stories（用户故事）

1. 作为刚开始一个新主题的学习者，我想用一条命令创建第一个笔记，这样我不用手工拼三段路径。
2. 作为学习者，我想让笔记文件落在主题目录下，这样「笔记按主题编号分目录」不需要我记住。
3. 作为学习者，我想让讲义目录里立刻有一个能跑的最小 `main.go`，这样我在写任何代码之前就能 `go run`。
4. 作为学习者，我想让作业目录有同样的可运行骨架，这样作业从一个能编译的状态开始。
5. 作为学习者，我想只建笔记、不建作业，这样「允许缺位」这条决策在自动化之后依然成立。
6. 作为学习者，我想让作业用它自己的题名，而不必和讲义同名，这样「作业按题名走」不会被工具推翻。
7. 作为学习者，我想显式提供带两位编号的主题，这样工具永远不会替我决定一个我没选过的顺序。
8. 作为学习者，当我不记得下一个编号时，我想让报错直接告诉我，这样我不用去数目录。
9. 作为学习者，我想让工具拒绝含大写、下划线、空格的名字，这样 slug 规则是被执行的，不是被记住的。
10. 作为学习者，我想用 `--title` 给笔记写入「中文（English）」形式的标题，这样术语约定落进文件而不是落进我的记性。
11. 作为学习者，我想在省略 `--title` 时用 slug 当标题，这样随手记一条不会被卡住。
12. 作为学习者，我想让生成的文件本身 `gofmt` 干净，这样 `gofmt -l .` 保持无输出。
13. 作为学习者，我想让生成的笔记不预置「要点」「TODO」这类段落，这样我不会被逼着填凑数内容。
14. 作为学习者，我想重复执行同一条命令是安全的，这样打错一个字不会让我丢掉已有文件。
15. 作为学习者，我想让已存在的文件以 `skip` 报告而不是静默覆盖，这样我知道工具动了什么、没动什么。
16. 作为学习者，我想用 `--dry-run` 先看到将被创建的完整路径，这样我能在落盘前核对。
17. 作为学习者，我想让工具只建我要求的那棵树，这样跑一次讲义生成不会在 `src/notes/` 下留下空目录。
18. 作为学习者，我想在仓库里的任何位置运行工具（包括 `src/lectures/...` 内部），这样我不必先 `cd` 回根目录。
19. 作为学习者，我想让工具在仓库之外拒绝运行，这样它永远不可能把骨架写到无关项目里。
20. 作为学习者，我想每条路径一行结果、结尾一行汇总，这样结果一眼可见。
21. 作为学习者，我想让退出码区分「用法错误」与「I/O 失败」，这样将来能接进脚本或 CI。
22. 作为学习者，我想在文档里看到一条 `go install`，这样装完之后任何 cwd 都能敲 `scaffold`。
23. 作为学习者，我想让这个工具不引入任何第三方依赖，这样仓库的门禁和「首个依赖才补 CI」的触发条件都不变。
24. 作为维护者，我想让「结构」只由一张种类表定义，这样以后加 `project` 是加一行表与一个模板，而不是改判定逻辑。
25. 作为维护者，我想让测试从 CLI 边界进入，这样行为被固定住，而私有函数可以自由重构。
26. 作为维护者，我想在工具区就有用法文档，这样下一个人不必读代码来学语法。
27. 作为未来的我，我想让 spec 与设计笔记互相印证，这样已定分支不会被重新讨论一次。
28. 作为未来的我，我想让 `AGENTS.md` 不再声称存在一个索引文件，这样没人会去重建一个我主动删掉的文件。
29. 作为未来的我，我想让术语表里有 `Scaffold`，且 `Tool` 条目不再描述「只有一个占位文件」，这样域语言与仓库一致。
30. 作为仓库本身，我想让 `tools/` 与 `src/` 保持隔离，这样「我在学的东西」与「服务于学习的程序」永远不会混在一起。

## Implementation Decisions（实现决策）

**模块与位置**

- 落在工具区 `tools/scaffold/`，与内容区 `src/` 隔离。入口 `main` 只做 wiring；核心在 `internal/scaffold`，只暴露一个 `Run`；测试在独立的 `test` 包（`package scaffoldtest`），不与核心代码混在同一目录。
- 零第三方依赖；只用标准库（`flag`、`os`、`path/filepath`、`regexp`、`strings`、`fmt`）。
- 命令名为 `scaffold`，与目录同名。

**结构的唯一权威**

- 一张种类表：`种类 → 内容区根 → 落点形态（单个文件 / 目录加入口文件）→ 内容模板 → 是否接受 --title`。
- 判定逻辑不硬编码任何具体种类；加一种类 = 表里加一行 + 一个模板常量。
- 不扫文件系统推断规则；文件系统扫描只用于「下一个可用编号」的提示。

**三个种类的内容契约**

| 种类 | 落点 | 是否接受 `--title` |
| --- | --- | --- |
| `note` | `src/notes/<topic>/<kp>.md` | 是 |
| `lecture` | `src/lectures/<topic>/<kp>/main.go` | 否 |
| `homework` | `src/homework/<topic>/<name>/main.go` | 否 |

- 主题：必须带两位编号，形如 `03-functions`；校验为 `^[0-9]{2}-[a-z0-9]+(-[a-z0-9]+)*$`。
- 知识点名 / 作业名：`^[a-z0-9]+(-[a-z0-9]+)*$`。
- 主题目录按「必要时创建」处理，且只在该种类落到的那棵树里创建。

**输入与命令面**

- 位置参数：`<kind> <topic> <name>`；`note` 额外接受 `--title`，其他种类不接受。
- flag 必须写在位置参数之前（标准库 `flag` 的语义）；用法提示照此书写。
- 每个种类一个独立 flag 集合，未知 flag 由标准库报错，不手写校验分支。
- 不做 `topic` 种类（只建目录、不建文件）；不预留 `project` 种类。
- 编号显式，不做自动分配；校验失败时错误信息包含「下一个可用编号」（扫描笔记区的主题目录，取最大编号 +1，两位补零）。

**生成内容**

- 笔记：一级标题加一个空行；标题取 `--title`，缺省用 slug。不预置任何章节骨架。
- 讲义 / 作业：`package main` 加空 `main()`，tab 缩进；不写注释、不留 TODO。
- 作业目录不放 `README.md`（题面按既有约定记在对应笔记里）。
- 模板以 Go 常量形式存在，不使用 `embed`，不使用 `text/template`。

**运行时契约**

- 目录已存在则静默跳过；文件用「不存在才创建」的独占语义写入。
- 已存在的文件报告为 `skip`，不覆盖；不提供 `--force`。
- `--dry-run` 打印计划，不触碰文件系统。
- 输出：每行 `create|skip <仓库相对路径>`，结尾一行 `N created, M skipped`。
- 错误输出到 stderr，带 `error:` 前缀。
- 退出码：`0` 全部成功或全部跳过；`1` 写入失败；`2` 用法或校验失败（参数个数、slug、编号缺失、不在本仓库内）。

**仓库根发现**

- 从当前工作目录向上查找 `go.mod`，其 module 必须是 `github.com/makursi/go-learning`；找不到或模块不符即退出 `2`。
- 本次不提供 `--root`。

**与既有决策的关系**

- 工具不参与索引：`src/notes/README.md` 已删除且暂不重建，三边对齐改由同名约定与全文搜索承载。
- 「一次建齐三边」不做；将来若要，是给命令加组合参数的增量特性。
- 不写 ADR：这一项在「难以逆转」上不成立。

## Testing Decisions（测试决策）

**什么算好测试**

只断言外部可观察的结果：文件系统上出现了哪些路径、内容是什么、stdout 与 stderr 写了什么、退出码是多少。不断言私有函数的形状、不断言中间数据结构、不为日志措辞做逐字匹配（只看 `create` / `skip` / 汇总这类稳定标记）。

**测试用的 seam**

- 单一 seam：CLI 边界。一个函数接收（参数、工作目录、stdout、stderr）并返回退出码；参数解析、校验、规划、写入、输出与退出码全部在这条线之下。
- 不引入文件系统抽象、不用 mock：测试在 `t.TempDir()` 里造一个带 `go.mod` 的假仓库根，用真实文件系统断言。
- 这是本仓库现有与新建 seam 里最高的一条；也是唯一一条。

**测什么**

- 三类落点与内容正确（含笔记标题缺省与 `--title` 两种情况）。
- 非法主题编号、非法名字被拒绝，退出码 `2`；「下一个可用编号」只加在主题错误上——名字没有编号可提示。
- 两位编号用尽（已有 `99-`）时不给数字提示，改说明编号已用尽；提示值本身必须能通过主题校验。
- `--dry-run` 不创建任何东西。
- 幂等：同一命令跑两遍，第二遍全 `skip`，退出码 `0`。
- 只建该种类的那棵树（跑讲义不在笔记区留目录）。
- 仓库之外运行时退出 `2`。
- 生成的 `main.go` 经 `format.Source` 处理前后完全相同（保证骨架永远 `gofmt` 干净）。

**先例**

本仓库此前没有任何 `_test.go`：作业明确不配测试，只有 `src/projects/` 的综合项目要求测试（尚不存在）。所以这是仓库的第一处测试，没有可参照的同类测试；约定由本 spec 确立——工具属于「服务于学习的程序」，按可复用程序对待，而不是按一次性作业答案对待。

**与先前讨论的一处收敛（已定）**

前一轮设计讨论里写的是「三个表驱动测试文件：slug 校验、规划纯函数、端到端」。按「尽可能少的 seam、尽可能高的 seam」原则，这里收敛成**一条从 CLI 边界进入的测试入口**：slug 与规划的行为通过 CLI 用例表达，而不是分别固定私有函数。实现里按能力分了多个测试文件，但它们共用同一个入口，seam 仍然是一条。代价是失败时的定位稍粗，收益是重构私有函数不必改测试。用户已确认这一收敛。

## Out of Scope（不在本次范围）

- 索引：不生成、不维护、不重建 `src/notes/README.md`。
- `project` 种类、`topic` 种类、`--with` 一类「一次建多条」的组合能力。
- `--force` 或任何覆盖已有文件的能力。
- 交互式向导。
- `--root` 或其他指定仓库根的方式。
- 自动分配编号。
- git 操作（分支、提交、PR 由人按仓库流程执行）与 CI 工作流（首个第三方依赖才触发）。
- ADR。
- Windows 短路径、UNC、符号链接、路径长度上限等平台边界的特殊处理。
