# Spec：作业目录的文件命名规范（一题一文件 + `NN-slug`）

## Problem Statement（问题陈述）

作业目录里的文件名，读者看了不知道该文件是哪道题、做的是什么。现在的名字分三种写法混用：

- **只有序号**：`pointer1.go` / `pointer2.go` / `for1.go` / `map2.go` / `slice2.go` / `struct1.go` / `error1.go`——文件里其实叫 `firstToX`、`updateScore`、`mustPositive`，信息全在代码里。
- **与目录同名**：`pointer/pointer.go`、`map/map.go`、`error-handling/error.go`、`struct/struct.go`——名字与目录重复，等于没名字。
- **语义名**：`type-conversion/bool-to-string.go`、`data-type/bool.go`——能读，但它们说的是「类型」而不是「这道题干什么」，且**只有一部分目录这么写**。

后果是双向的：

- **自己复习时**：想回看「结构体值 vs 指针那道题」，得先打开 `main.go` 推顺序，再逐个文件找函数名。
- **agent 阅读时**：拿到「第 3 题」无法定位文件；每次都要先读一遍同目录所有文件才能判断哪个是入口、哪个是辅助。半套规范比没规范更费判断力。
- **还有两个目录形状不同**：`go-function/` 与 `varibles/` 把全部题目塞在 `main.go` 里，其余目录是「一题一文件 + main 调度」。同一层目录有两种形状，读者得先辨认。

另有一处拼写错误：作业与笔记的目录/文件名都写作 `varibles`（应为 `variables`），会长期污染搜索与路径。

## Solution（方案）

把作业目录固定成一种形状、一种命名：

- **一个主题一个作业目录**（不是一题一目录），目录内**一题一文件**、外加一个只做调度的 `main.go`。
- 文件名 **`NN-slug.go`**：`NN` 是这道题在该目录内的顺序（两位补零，从 `01` 开始），`slug` 是小写连字符短语，说明**这道题在验证什么**，不是类型名、不是「练习 1」。
- **文件名与入口函数绑定**：`03-comma-ok-and-delete.go` ↔ 入口函数 `CommaOkAndDelete()`。题目自己的辅助函数、类型、方法都留在同一文件里，不另开文件。
- **题目注释统一**放在文件最上方、`package` 声明之前，以 `// 题目：` 开头。
- `main.go` 里只留调度：按题号顺序调用各题的入口函数，一个 `go run` 跑完整个主题。

`go-function/` 与 `varibles/` 也拆成一题一文件，把两种形状合成一种。`varibles` 的拼写一并改为 `variables`。

这条规范进 `AGENTS.md`（目录形状与命名规则）、`GLOSSARY.md`（新增「练习题（Exercise）」，并修订「作业（Homework）」的定义），`tools/scaffold` 的用法文档补一句「生成作业目录之后，题目文件按 `NN-slug` 加」。

## User Stories（用户故事）

1. 作为学习者，我想让每个作业文件的名字直接说明这道题做什么，这样我不用打开 `main.go` 推顺序就能找到想复习的那道题。
2. 作为学习者，我想让文件名带两位题号，这样我在目录列表里看到的顺序和我学习、笔记的顺序一致。
3. 作为学习者，我想让文件名与入口函数同名（kebab 化），这样「文件叫 `02-swap.go`、函数叫 `Swap`」是可直接推导的，不用记。
4. 作为学习者，我想让 `main.go` 只做调度，这样我想只跑某一道题时，知道该注释哪一行。
5. 作为学习者，我想让 `main.go` 按题号顺序调用，这样 `go run` 的输出顺序与题号一致，对照笔记时不用来回翻。
6. 作为学习者，我想让题目注释固定在文件顶部，这样在编辑器大纲里一眼能看到这道题的要求。
7. 作为学习者，我想让 `go-function` 和 `varibles` 也拆成一题一文件，这样我不用每次先辨认这个目录是哪种形状。
8. 作为学习者，我想让 `varibles` 的拼写修正为 `variables`，这样目录名、笔记名与搜索都能对上正确的词。
9. 作为学习者，我想让 `data-type` 与 `type-conversion` 这类「本来就还行」的名字也统一成同一套格式，这样我不必为不同目录切换阅读策略。
10. 作为学习者，我想让重命名保留 git 历史，这样我回看某道题以前的写法时不会被 `git mv` 截断。
11. 作为学习者，我想让重命名不改变任何题目的逻辑与输出，这样这次改动是纯整理，没有行为变化需要重新理解。
12. 作为学习者，我想让每个作业目录仍然一条 `go run` 跑完，这样我不需要记几十条命令。
13. 作为维护者，我想让仓库约定（`AGENTS.md`）里描述的形状与实际一致，这样「文档说的」和「目录里长什么样」不再对不上。
14. 作为维护者，我想让术语表对「作业」和「练习题」有分开的定义，这样「一个作业目录」与「一道练习题」不再被同一个词指代。
15. 作为维护者，我想让这次整理按目录逐个提交，这样出问题时能只回滚一个主题。
16. 作为维护者，我想让这次整理走一次完整的门禁，这样纯整理不会以编译失败为代价。
17. 作为维护者，我想让冒烟检查覆盖每个作业目录，这样「文件名改了但函数调用没跟上」这类错误会在合并前暴露。
18. 作为 agent，我想从文件名直接推断这道题在验证什么，这样我不必先读完整个目录才能回答「第 3 题在哪」。
19. 作为 agent，我想让入口函数与文件一一对应，这样定位入口不需要猜测。
20. 作为 agent，我想让目录形状统一，这样我只需要一套读取规则，而不是按目录猜形状。
21. 作为 agent，我想在仓库约定里读到这条规则，这样下次新增题目时我按规则命名，而不是沿用「`xx1`、`xx2`」的旧习惯。
22. 作为未来的我，我想让这次规范有 spec 与设计记录，这样「为什么不是一题一目录」这个问题只推导一次。

## Implementation Decisions（实现决策）

**目录粒度**

- 维持现状的**一主题（作业）一目录**，不改成「一题一目录」。理由：每题独立 `go run` 的收益已由「`main.go` 里注释切换」覆盖，而一题一目录会把目录数抬到四倍、把题目注释分散到各自的 `main()`，检索反而更累。
- `AGENTS.md` 里「每道题一个目录」的表述改成「每个作业一个目录、一题一文件」——文档跟着实际走。

**文件名规则**

- 形如 `NN-slug.go`：`NN` 两位补零从 `01` 起，`slug` 为英文小写连字符短语。
- `slug` 描述**这道题验证什么**（如 `comma-ok-and-delete`、`struct-value-vs-pointer`），不描述类型、不描述语言特性、不用「练习」字样、不与目录同名。
- 题号 = 该目录内的学习顺序，与对应笔记里题目的出现顺序一致。
- 插入新题导致后续题号变动时，用 `git mv` 逐文件改，保留改名历史。

**文件名与函数名绑定**

- 每个练习文件暴露一个**入口函数**（被 `main` 调用），函数名为文件 slug 的 PascalCase 形式：`02-swap.go` ↔ `Swap()`。
- 辅助函数、被定义的类型与方法留在该题自己的文件里，不另开文件；一题内部多个辅助函数不改变「一题一文件」。
- 现有把整道题写成 `main` 内联代码的两个目录（`go-function`、`varibles`）需要把内联逻辑提取成入口函数，再按题拆文件。
- 语义不清的函数名一并修正（如把乘法表那题的 `nn` 改成能读出的名字），但**不改任何题目的逻辑与输出**。

**题目注释**

- 统一在文件最上方、`package` 声明之前，以 `// 题目：` 开头，后接这道题的要求。
- 原来写在函数体内、或写在 `main.go` 顶部的题目注释，随之搬到各自文件顶部。

**`main.go`**

- 只做调度：按题号顺序调用各入口函数，不内联题目逻辑。
- 保留注释掉某题的用法（逐题调试时的开关），但默认全部打开。

**目录与文件名迁移范围**

- 全部 11 个作业目录都统一到这套形状（含本来「还行」的 `data-type` 与 `type-conversion`）：半套规范比没规范更费判断力。
- `go-function` 与 `varibles` 拆成一题一文件。
- `go-if` 仍是空骨架（只有 `main.go`），不强行造题；等真正做这道题时按规范新增文件。
- `varibles` → `variables`：目录名与对应笔记文件名一起改，作为独立提交。

**文档同步**

- `AGENTS.md`：目录约定表里 `src/homework/` 的「形态」列改为「`main.go` 调度 + `NN-slug.go` 一题一文件」；正文补一条命名规则。
- `GLOSSARY.md`：新增「练习题（Exercise）」——作业目录里一题一个文件、带入口函数的最小单位；修订「作业（Homework）」——一个主题下的一组练习，含一个调度用的 `main`。
- `tools/scaffold` 的用法文档：补一句「生成作业目录后，题目文件按 `NN-slug` 新增」。
- 不在本次扩展 `scaffold` 的能力（`--exercise` 参数单独开票）。

**交付**

- 一个分支、一个 PR；提交按「一个目录一刀」切，`variables` 改名单独一刀，文档同步最后一刀。理由：出问题时只回滚一个主题，review 时每刀只读一个目录。
- 不改任何题目的运行结果，所以每一刀的验证标准相同：门禁绿 + 该目录 `go run` 输出与改动前一致。

## Testing Decisions（测试决策）

**什么算好测试**

这次改动不引入新行为，唯一的外部可观察契约是**每个作业目录仍然一条 `go run` 跑通、输出与改动前一致**。因此不写新的单元测试，用「门禁 + 逐目录冒烟」把契约固定住；断言只看退出码与输出，不看文件名。

**seam**

- 不新增 seam。仓库当前的测试 seam 只有一个：`scaffold` 的 CLI 边界（参数 + 工作目录 + 两个流 → 退出码）。本次不碰 `tools/` 的任何代码，该 seam 与其测试完全不动。
- 内容区的验证不引入测试框架：作业按既有约定不配 `_test.go`，这次也不因为「改了名字」而破例。

**测什么**

- 门禁三条：`gofmt -l .` 无输出、`go vet ./...`、`go build ./...`。
- 逐目录冒烟：11 个作业目录各 `go run` 一次，断言退出码为 `0`；对改动前有确定的输出的目录，比对输出内容未变。
- 旧名残留：全仓搜索被替换掉的旧文件名与错误拼写，确认没有文档、注释或命令示例还指着它们。
- 每个目录的 `main.go` 调用顺序与文件题号一致（人眼核对一次，不写成测试）。

**先例**

仓库唯一的测试先例是 `tools/scaffold` 的外部测试包（单一 CLI 入口 + 真文件系统）。本次不新增同类测试，因为被整理的对象不是程序而是内容——内容区的正确性用「能编译、能跑、输出没变」表达，与 `AGENTS.md` 里「作业靠 `go run` 看输出」一致。

## Out of Scope（不在本次范围）

- 改成「一题一目录」（每个练习题一个可执行目录）。
- 修改任何题目的答案逻辑、题目要求或输出内容；只动命名与组织。
- 给 `tools/scaffold` 增加 `--exercise` 一类参数（单独开票）。
- 给作业补 `_test.go` 或引入批量运行脚本。
- 追加新题目（`go-if` 的空骨架保持空）。
- 主题编号（`01-go-language`）与笔记目录的重新划分。
- 重写 git 历史（改名用 `git mv`，不 squash 掉旧路径）。

## Further Notes（补充说明）

- 现状核实（2026-10-28）：11 个作业目录中，7 个用「序号名」（`pointer1.go` 等），2 个用语义名（`type-conversion/`、`data-type/`），2 个只有 `main.go`（`go-function/`、`varibles/`）；另有 `varibles` 的拼写错误。
- 已知的两处小债一并处理：`error1.go` 的入口函数 `nn` 语义不明；`data-type/interface.go` 的入口函数与类型定义同名（`Interface`），迁移时按「入口函数 = 文件 slug 的 PascalCase」统一。
- 这次是纯整理，风险在「漏改一处调用」而不是逻辑。因此冒烟按目录逐个跑，并在每一刀的提交信息里写明该目录改了哪些文件。
- 「为什么不是一题一目录」的推导值得记进设计笔记，避免下次重提；本次不写 ADR（可逆、加回成本低）。
