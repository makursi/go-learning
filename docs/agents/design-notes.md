## 已定分支

### 内容区 / 工具区分离（`src/` 与 `tools/`）

全部学习内容放在 `src/` 之下：`src/notes/` `src/lectures/` `src/homework/`，将来还有 `src/projects/`。服务于学习本身的程序放在 `tools/`（目前只有占位文件，预留给一个自动创建目录结构的 CLI）。

这项决定覆盖了此前的「三类放根级」方案（见下方已否分支）。已知代价：将来从内容里长出的可复用包，导入路径是 `github.com/makursi/go-learning/src/...`，比无 `src/` 时多一级。

因为不符合 Go 的一般习惯，`AGENTS.md` 里专门写了一条「`src/` 是刻意保留的，不要拍平」，防止后来的 agent 看到就顺手搬走。

### 模块身份

`module go-start` → `github.com/makursi/go-learning`。仓库已是 public，将来从笔记里长出的可复用包需要与远端一致的导入路径。

### 单一根模块

一个根 `go.mod` 管全部内容（含 `src/` 与 `tools/`），不给单个练习建 `go.mod`，暂不引入 `go.work`。

收益：根目录一条 `go build ./...` 就能验证全部代码，依赖集中升级。代价：各练习共享同一份依赖声明，两个练习要不同版本同一库时会打架 —— 学习阶段几乎不可能发生，真发生再拆，拆比提前铺 `go.work` 便宜。

### 三边对齐（宽松）

笔记、讲义、作业靠同一个主题编号对齐，**允许缺位**，不强制每个知识点齐三份。

命名规则：`src/notes/02-data-structures/maps.md` ↔ `src/lectures/02-data-structures/maps/` 同名；作业按题名走 `src/homework/02-data-structures/fruit-count/`，不要求和讲义同名。

曾经靠 `src/notes/README.md` 的主题索引承载「缺的留空」。2026-10-23 用户删除了该文件并决定暂不重建（见文末「第二轮」），所以三边对齐现在的唯一载体是**同名约定 + 全文搜索**；索引已从「前提」降级为「待补的便利层」，不再是一条成立条件。

强制齐三份会在「这个知识点我写不出作业」时逼着造垃圾。

### 命名与语言

理由：路径要过终端、URL、Go 工具链和编辑器搜索，中文路径在 Windows 上的坑不值得为省一次翻译去踩；正文是给自己复习的，中文读得快。

## 第二轮：工具区 CLI（`scaffold`）

### 问题

在 `tools/` 里做一个 Go CLI，按学习内容的结构建出目录与骨架文件，与 `src/` 的内容隔离。用户给的三条要求：最小化、可拓展性强、可维护性高。

起点（2026-10-23 核实）：`tools/` 只有占位 `README.md`，全仓零 Go 代码；`src/` 下三个目录全空；`src/notes/README.md`（主题索引）已在工作区删除且未提交；单根模块 `github.com/makursi/go-learning`，go 1.27.1，`GOBIN` 在 PATH 上。

### 已定分支

**位置与代码形状**：`tools/scaffold/`，零第三方依赖，分三层：根目录 `main.go` 只做 wiring（取 cwd → 调 `Run` → 透传退出码）；`internal/scaffold/` 是核心，`Run(args, cwd, stdout, stderr) int` 是唯一对外入口；`test/` 是外部测试包（`package scaffoldtest`），只经 `Run` 进入。结构的唯一权威是 `internal/scaffold/kinds.go` 里的一张 `Kind` 表（种类 → 根目录 → 落点形态 → 内容模板 → 是否接受 `--title`）；规划层是纯函数（输入请求与一个「这个路径存在吗」的探测函数，输出一条待执行的指令），文件系统读写只在执行层。加一个种类 = 表里加一行 + 一个模板常量，判定逻辑一行不动。

一开始没有这一层：`--dry-run` 用 `Lstat`、真实运行用 `OpenFile` 各判一次「存不存在」。code-review 指出这既与本节的说法不符，也让两条路径可能给出不同答案，于是补了 `plan` / `execute` 的切分。

同一次 review 之后，用户要求核心代码与测试分目录。Go 允许「只含 `_test.go` 的目录」作为独立测试包存在（实测 `go build ./...` 与 `go vet ./...` 都不报错），于是核心搬进 `internal/scaffold/`、测试搬进 `test/`，对外只留一个导出的 `Run`。这覆盖了 Q2 的「单一 `package main`」：代价是入口必须导出，收益是工具根目录只剩入口与文档。

不选 `main.go` + `internal/` 分层：同包测试足够用，多一层目录换不到任何边界。不选外部配置驱动的通用引擎：要额外养配置格式、schema 与错误处理，而本仓没有「别人来加种类」的诉求。不选 cobra：为三条命令引入首个第三方依赖，还会触发 `AGENTS.md` 里「第一次引依赖就补 CI」的条件。

**原子单元：单边**。一次调用只落一个种类的一个条目。三个种类：`note`（笔记文件）、`lecture`（讲义目录 + `main.go`）、`homework`（作业目录 + `main.go`）。主题目录按 `mkdir -p` 语义按需创建，**只建该种类用到的那棵树**——建讲义不会顺手在 `src/notes/` 下造一个空目录。不做「一次建齐三边」，因为它与两条既有决策冲突：允许缺位、作业名不必等于讲义名。将来真要「三边一起」，是加 `--with` 的增量特性，不返工。

**命令面**：

```sh
scaffold note     --title "映射（Maps）" 03-functions maps
scaffold lecture  03-functions maps
scaffold homework 03-functions fruit-count
```

flag 必须在位置参数之前。这是标准库 `flag` 的语义，也是「不写自己的参数解析器、不为三条命令引 cobra」的直接代价：`note 03-functions maps --title x` 会在第一个位置参数处停止解析，`--title` 直接丢掉。所以统一成 flag 在前，用法提示也照此书写。

每个种类一个独立的 `flag.FlagSet`，未知 flag 由标准库报错，不手写校验。不做 `topic` 种类（空目录 git 不跟踪，单边模型下主题目录是副作用，建出来立刻不可见）。暂不预留 `project` 种类（`src/projects/` 还不存在，加它是纯增量）。

**路径与编号**：主题必须带两位编号，`^\d{2}-[a-z0-9]+(-[a-z0-9]+)*$`；知识点与作业名用 `^[a-z0-9]+(-[a-z0-9]+)*$`。落点：`src/notes/<topic>/<kp>.md`、`src/lectures/<topic>/<kp>/main.go`、`src/homework/<topic>/<name>/main.go`。

编号**显式**：不接受「只给名字让工具分配」。自动编号会让「谁先建谁占号」变成隐藏状态。校验失败时错误信息附上「下一个可用编号是 03」（扫 `src/notes/` 现有最大编号 +1，格式 `%02d`），便利性靠提示而不是靠魔法。

**模板**：Go 常量，不进 `embed`、不用 `text/template`（模板目前没有第二个变量，常量比「模板名 → 文件」的弱链接更原子）。笔记 = `# <title>` 加一个空行，`--title` 缺省时用 slug；讲义与作业 = `package main` 加空 `main()`，tab 缩进，保证 `gofmt -l` 无输出。三类都不预置「要点」「TODO」这类逼人填空的段落。作业目录不放 `README.md`，题面按既有约定记在对应 Notes 里。

**运行时契约**：目录已存在则静默跳过；文件用 `O_EXCL` 创建，已存在则打 `skip` 继续。不提供 `--force`——那是学习内容的误删入口，要覆盖就手删。`--dry-run` 打印计划、不落盘。输出每行 `create|skip <仓库相对路径>`，结尾一行 `N created, M skipped`；错误走 stderr 并加 `error:` 前缀。退出码：`0` 全部成功或全部跳过、`1` I/O 失败、`2` 用法或校验失败（参数个数、slug、编号、不在本仓内）。

**仓库根发现**：从 cwd 向上找 `go.mod`，模块路径必须是 `github.com/makursi/go-learning`，否则报错退出 `2`。这样在 `src/lectures/...` 里敲命令也能用。`--root` 这次不做。

**调用方式**：日常 `go run ./tools/scaffold ...`；`tools/scaffold/README.md` 另外给一条 `go install ./tools/scaffold`（装进 `GOBIN`，已在 PATH 上），装完任何 cwd 都能敲 `scaffold`。

**测试**：要测。工具的价值正是「路径和编号不会错」，这恰恰是人手 `go run` 验不出来的。测试只从**一条 seam**进入——CLI 边界上的「参数 + 工作目录 + 两个输出流 → 退出码」，不引文件系统抽象、不 mock，在 `t.TempDir()` 里造带 `go.mod` 的假根用真文件系统断言。用例按能力分文件（落点、校验、编号、幂等、dry-run、汇总、根发现、用法）；能表驱动的（slug 与编号拒绝、用法错误）用表，其余是单例场景——「一个测试文件」不是目标，「一条 seam」才是。覆盖：三类落点与内容、slug 与编号拒绝（含「下一个可用编号」与两位编号用尽）、`--dry-run` 不落盘、幂等与 `skip`、只建该种类的树、仓库外拒绝、退出码 `0/1/2`。额外一条断言：生成的 `main.go` 过 `format.Source` 不变，骨架的 gofmt 干净不靠人记。

spec 里一度写过「slug / 规划 / 端到端三个测试文件」，落到了「一条 seam」上：把私有函数分别固定住会换来更准的失败定位，代价是每次重构都要改测试；工具只有几百行，前者不值得。

**索引**：工具不参与。用户删除 `src/notes/README.md` 后决定暂不重建，`AGENTS.md` 里「新增知识点时同时更新索引」那条一并删掉。三边对齐改由同名约定 + 全文搜索承载。

**文档与交付**：`tools/README.md` 从占位改写成工具区索引（链到 `tools/scaffold/README.md`）；`AGENTS.md` 更新三处——`tools/` 段落、门禁里的「空模块例外」（有包之后不再触发）、索引那条；`GLOSSARY.md` 增 `Scaffold` 并改 `Tool` 的定义。不写 ADR：三条门槛里的「难以逆转」不成立，工具随时可改。

## 第三轮：砍掉讲义这一类内容

### 问题

内容模型是三类：笔记 / 讲义 / 作业。用下来之后用户判断「讲义」多余：它和作业目录里的代码形状相同、内容重叠，却要独占第三棵树、一套独立的命名规则，以及仓库里每一处「三边对齐」的说法。它同时让其他约定持续付息——工具要多养一条命令与一张三行的种类表，术语表里 `Homework` 只能靠「与 Lecture 的区别」来定义，文档里二十余处要向它解释。

核实（2026-10-25）：`src/lectures/` 10 个目录、10 个 `main.go`，9 个是生成后从未填过的空骨架，唯一有内容的 `hello-world` 只是一句 `fmt.Println`，而 `src/notes/01-go-language/hello-world.md` 已经承载同一个知识点；`src/notes/` 里没有任何一处引用讲义路径；工作区干净、在 `main` 上，讲义全部已提交（`28c0df9`），删掉可从历史取回。

起初的怀疑是「是不是骨架从没填过，所以看着空」——如果是那样，删完讲义作业区会以同样方式变空，问题没解决。用户确认要删的是**概念**：跟课敲一遍的产物既不是复习材料，也不是自己的答案，笔记里的围栏代码块更能配合文字解释。所以按「这一类没有独立价值」处理，而不是「这一批目录没填」。

### 已定分支

**内容模型收敛为两类**：笔记（Note）+ 作业（Homework）。`src/lectures/` 整棵删除，包括 `hello-world`——不迁移、不归档。理由：示例本身不是资产，它要的是「第一次跑起来」的手感，那由笔记里的代码块承载。

**`scaffold` 砍掉 `lecture` 命令**：种类表删一行，`lecture` 走未知种类路径（stderr 报错、退出 `2`、不写任何东西），不留「已移除，请用 homework」的特判。特判是给过渡期和别人的，这里只有一个人用；而它会永久留在一个几百行的工具里，等着被误读成「讲义仍是一种被禁用的种类」。其余行为逐字不变——这是减法，不是重构。

**表驱动结构保留**：两个种类仍然一个落成单文件、一个落成「目录 + 入口文件」，形状差异还在，种类表继续是内容区结构的唯一权威。不因为只剩两行就内联成 `if`：那会顺手把「加一类只加一行」这条性质弄丢。

**`src/projects/` 也从模型里拿掉**：仓库约定与术语表都不再描述它。用户选的是「暂时不留」——那么域文档就不该写一个不存在的类，术语表收的是现在的语言，不是愿望清单。加回路径（种类表加一行 + 一个内容生成器）记在本节与 `AGENTS.md` 的护栏里，不占域文档。

**术语表只删不注**：`Lecture` 与 `Project` 两个条目删除，不留「已移除」标记；`Homework` 改成正面定义，不再靠「与 Lecture 的区别」存在；`Content` / `Topic` / `Scaffold` 三处去掉第三边。留死词会让下一个 session 以为讲义还在。

**`AGENTS.md` 加一行护栏**：与既有的「`src/` 是刻意保留的，不要拍平」同构——那条防的是重构冲动，这条防的是「补齐对称」冲动：删掉第三个种类之后仓库看起来不对称，下一个 agent 很容易判断成「这里缺了讲义，我补上」。

**门禁那句补一句极短理由**：拿掉 `src/projects/` 这个参照物之后，「作业不配 `_test.go`」会变成没有来由的禁令，所以写清「一次性答案 vs 长期程序」。

**spec 快照冻结**：`docs/specs/scaffold-cli.md` 里 `lecture` 出现 9 次，一律不改。它记录的是「当时发布过什么」，改它等于伪造历史。本次改动另有一份 spec（`docs/specs/remove-lectures.md`，权威副本是 issue #20）。

**设计笔记顶部加状态行**：在标题下声明「现状以最新一轮为准」，前面各段保留原样。`design-notes` 的价值一半在「现在是什么」、一半在「当时为什么」，回头修订前面各段会把后者洗掉。

**测试按同一 seam 减少用例**：不新增 seam，仍只从 CLI 边界（参数 + 工作目录 + 两个输出流 → 退出码）进入。讲义用例删除，其中「生成的入口文件是 `package main` 且有 `main()`」的 AST 断言并进作业用例，覆盖不减；其余字面量换成作业；未知种类表补一行 `lecture`。夹具文件在删掉唯一用例后只剩共享夹具，更名 `harness_test.go`。

### 已否分支

- **把 `hello-world` 挪进作业区**：它的价值是「第一次跑起来」的手感，笔记里贴一段代码块就够；挪进作业等于为一句话造一个目录，还会让作业区出现不是自己写的题。
- **给 `lecture` 留友好提示（「已移除，改用 homework」）**：过渡期只有用户一个人，本文件已写明原因；特判会永久留在工具里等着被误读。
- **保留 `Project` 作为「未来槽位」**：它存在的全部理由就是「不占实际结构」，但用户选的是「暂时不留」；域文档描述不存在的类，等于把愿望清单混进模型。
- **反向修订 `docs/specs/scaffold-cli.md`**：快照记的是历史，改它就是伪造历史；现状由本文件承载。
- **为这次移除写 ADR**：三条门槛里的「难以逆转」不成立——加回来只是种类表一行，理由留在本节即可。
- **只留裸规则、不写「作业不配测试」的理由**：多 12 个字换掉将来一次重新争论，成本收益不对称。
- **顺手把种类表内联成 `if`**：形状差异还在（文件 vs 目录 + 入口），表仍然是唯一权威；内联会丢「加一类只加一行」。
- **先删内容、后改工具**：中间态里工具还能把刚删的树重新生成回来，自相矛盾。所以 ticket 顺序是工具在前。

### 待定分支

无。

## 第四轮：作业目录的文件命名

### 问题

作业目录里三种命名混用：`pointer1.go` / `for2.go` 一类只有序号，信息全在函数的 `updateScore`、`mustPositive` 里；`pointer/pointer.go`、`map/map.go` 与目录同名，等于没名字；`type-conversion/` 一类的语义名只覆盖了一部分目录。复习时要先打开 `main.go` 推顺序，agent 拿到「第 3 题」也定位不到文件。另有两个目录（`go-function`、`varibles`）把全部题目内联在 `main` 里，同一层目录出现两种形状；`varibles` 还是拼写错误。

### 已定分支

**一题一文件 + `NN-slug.go`**：两位题号（顺序 = 学习顺序 = 笔记里出现的顺序）+ 说明这题验证什么的 slug；文件名与入口函数一一对应（`02-swap.go` ↔ `Swap()`），辅助函数与类型留在同一文件；题目注释统一在文件最上方、`package` 之前，以 `// 题目：` 开头；`main.go` 只做调度。

**不走「一题一目录」**：一题一目录能让每题单独 `go run`，但那点收益已经被「`main` 里注释切换」覆盖；代价是目录数四倍、题目注释散进各自的 `main()`、检索变三层。`AGENTS.md` 里原来写的「每道题一个目录」与实际早已不符，这次让文档跟实际走。

**十一个目录一次统一**：半套规范比没规范更费判断力——`bool-to-string.go` 与 `bool.go` 摆在一起，人每次都得先确认哪个目录用哪套规则。

**`go-function` 与 `variables` 拆成一题一文件**，`varibles` → `variables` 单独一刀（拼错的 slug 会长期污染搜索与导入路径）。

**defer 顺序与 panic/recover 合成一道题**：defer 的后进后出只有在「注册与返回发生在同一函数里」时才观察得到；拆成两个文件会让 `C B A` 提前打印，输出与整理前不一致。

**纯整理**：不改任何题目的逻辑与输出。验证方式是整理前给 11 个目录各存一份基线输出，整理后逐个 `go run` 比对（含 map 遍历的三个目录按排序后比较）。

**文档同步**：`AGENTS.md` 写清形状与命名规则；`GLOSSARY.md` 新增「练习题（Exercise）」、把「作业（Homework）」改成「一个题目集 + 一个只做调度的 main」；`tools/scaffold` 用法文档补一句生成之后怎么加题目文件。

### 已否分支

- **一题一目录**：见上，收益已被覆盖，成本是目录数四倍。
- **只改最烂的三个目录（pointer / go-for-loop / map）**：留下半套规范，读者仍要按目录猜规则。
- **`data-type`、`type-conversion` 保留原名只加题号**：它们的 slug 说的是类型或方向，不是「这题验证什么」，不统一就还是两套口径。
- **把 `nn`、`IntCovers` 这类名字留下来**：文件名与函数名绑定之后，这些名字会成为唯一不透明的入口。
- **让 `scaffold` 直接生成 `NN-slug.go`**：工具只建目录与调度用的 `main`，题目内容本就由人写；加参数是另一件事，需要单独开票。
- **为这次写 ADR**：可逆（改名可再改回），加回成本低，理由留在本节即可。

### 待定分支

- `scaffold` 是否增加 `--exercise` 一类参数，用于生成题目文件骨架。等真正觉得「每加一题都要手写文件头」烦了再说。
